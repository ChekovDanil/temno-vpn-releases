# Сборка и распространение TEMNO VPN

## Общий порядок

1. Собрать кандидат из зафиксированного commit SHA.
2. Прогнать платформенные тесты на чистом окружении.
3. Подписать производственным сертификатом или ключом платформы.
4. Проверить подпись уже упакованного файла.
5. Для macOS дополнительно выполнить notarization, stapling и проверку
   Gatekeeper на чистом Mac.
6. Вычислить SHA-256 и размер финального файла. После этого файл не менять.
7. Создать GitHub Release с уникальным тегом и загрузить asset один раз.
8. Добавить checksum, обновить `latest.json` и соответствующий платформенный
   манифест одним изменением.
9. Запустить `scripts/validate_catalog.py` и тесты.
10. После пользовательской проверки продвигать тот же бинарный файл из beta в
    stable. Пересобранный файл всегда получает новую версию и новый тег.

`latest.json` остаётся совместимым с текущим Windows-клиентом. Клиент читает
только `stable` и `beta`; `internal` не участвует в обновлениях. Даже для
опубликованного beta-кандидата поле `automaticUpdate` остаётся `false`, пока
конкретная платформа не пройдёт все проверки выпуска.

## Windows

- Релизные файлы: подписанный installer и, при необходимости, portable ZIP.
- Stable требует Authenticode-подпись. До её появления 0.9.12 RC остаётся beta,
  а `automaticUpdate` — `false`.
- Автоматическая установка включается только после проверки подписи каталога и
  загруженного установщика внутри клиента.

## Android

- Для Google Play собирается подписанный release AAB.
- Для прямой установки можно публиковать только подписанный release APK с
  неизменяемой ссылкой и SHA-256. Все ABI одного кандидата перечисляются в
  `variants`, основной файл повторяется в `artifact` для совместимости.
- Production keystore хранится в защищённых секретах CI и не попадает в
  репозиторий.
- Debug APK не загружается в GitHub Releases и не получает публичную ссылку в
  каталоге. Его состояние можно обозначить только в `internal`.
- Кандидат без проверки на физическом устройстве публикуется только как
  prerelease с `physicalDeviceTested: false` и без автообновления.

## iOS и iPadOS

- Сборка выполняется на macOS через Xcode с Apple Team, App Group, Keychain
  Group и Network Extension capability.
- Тестирование пользователей идёт через TestFlight, релиз — через App Store.
- Публичный IPA и прямая GitHub-ссылка на IPA запрещены.
- В каталоге публикуется только ссылка магазина после фактической доступности.
- До готовности приложения в `internal` можно указать handoff-архив исходников
  для Xcode. Он обязан явно содержать `vpnReady: false` и
  `physicalDeviceTested: false` и не считается IPA или приложением.

## macOS: прямое распространение

- TEMNO собирается с Packet Tunnel System Extension.
- Приложение и вложенные компоненты подписываются Developer ID и Hardened
  Runtime.
- Готовый DMG или PKG отправляется Apple на notarization, затем ticket
  прикрепляется через stapling.
- Каталог разрешает публикацию только при `signed`, `notarized` и `stapled`,
  равных `true`.
- Пока эти проверки не пройдены, `stable.macos` и `beta.macos` остаются `null`.
- Handoff-архив исходников может находиться только в `internal`; его ссылка не
  является ссылкой на DMG/PKG и никогда не используется автообновлением.

Подробная инструкция сборки находится в проекте Apple:
`apps/Temno.Apple/MACOS-DIRECT-RELEASE-RU.md`.

## Размещение

- История и бинарные файлы: GitHub Releases.
- Каталог: `https://raw.githubusercontent.com/ChekovDanil/temno-vpn-releases/main/updates/latest.json`.
- Сайт и API: Amvera. Перезапуск сайта не меняет ссылки на уже опубликованные
  приложения.
- Каждый URL в каталоге содержит точный тег и имя asset. Alias `latest` не
  используется.
